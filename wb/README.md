# Автоответы на отзывы Wildberries (JE LA PECHE)

Этот проект помогает автоматически отвечать на отзывы покупателей в Wildberries.

Если говорить совсем просто:
1. Скрипт забирает новые отзывы из WB.
2. Определяет тип отзыва (позитив, негатив по размеру, по качеству и т.д.).
3. Собирает вежливый ответ по нужному сценарию.
4. Проверяет текст (обращение «Вы», подпись, длина).
5. В тестовом режиме только показывает ответ.
6. В боевом режиме отправляет ответ в WB.

---

## 1) Что нужно для запуска

Вам нужны:
- Python 3.10+
- токен WB
- ключ OpenAI API

Установите зависимости:

```bash
pip install -r requirements.txt
```

Создайте файл `.env` рядом с `wb_reviews_reply.py`:

```env
WB_TOKEN=ваш_токен_wb_БЕЗ_BEARER
OPENAI_API_KEY=ваш_openai_api_key
OPENAI_MODEL=gpt-4o-mini
OPENAI_PROJECT=
DRY_RUN=1
MAX_COUNT=50
OPENAI_MAXTOKENS=220
```
Важно: в `WB_TOKEN` указывайте только сам токен, без слова `Bearer`, без кавычек и без лишних пробелов.

---

## 2) Как запускать локально

Обычный запуск:

```bash
python wb_reviews_reply.py
```

По умолчанию стоит `DRY_RUN=1`, поэтому ответы **не отправляются в WB**.

---

## 3) Как тестировать без отправки в WB

### Вариант A (самый важный)
Убедитесь, что в `.env` стоит:

```env
DRY_RUN=1
```

Тогда скрипт покажет в консоли:
- id отзыва и оценку,
- категорию,
- причины классификации,
- итоговый текст ответа.

### Вариант B (тесты)

```bash
pytest -q app/tests
```

---

## 4) Как включать боевой режим

В `.env` поменяйте:

```env
DRY_RUN=0
```

После этого запуск:

```bash
python wb_reviews_reply.py
```

Теперь ответы будут отправляться в WB. Отзывы с оценкой ниже 4 пропускаются до генерации; флаг ручной обработки
(раздел 8) публикацию не блокирует.

---

## 5) Где менять правила ответов

Основные файлы:

- `app/config/classification_rules.json` — правила классификации отзывов (ключевые слова, короткий отзыв и т.д.)
- `app/config/scenarios.json` — сценарии ответа для каждой категории

Если хотите изменить, как определяется «негатив по размеру» или «короткий отзыв», меняйте `classification_rules.json`.

Если хотите изменить, *как именно отвечаем* для категории, меняйте `scenarios.json`.

---

## 6) Где менять фирменный стиль

Файлы стиля:

- `app/prompts/system_ru.txt` — общий тон бренда (вежливо, живо, признавать проблему)
- `app/prompts/user_template.txt` — шаблон того, какие данные передаются модели
- `app/core/postprocess.py` — технические правила текста:
  - подпись,
  - «Вы/Вам/Ваш» с большой буквы,
  - приветствие,
  - ограничение длины,
  - анти-повторы.

---

## 7) Как добавлять новые категории отзывов

Простой порядок:

1. Добавьте категорию в `app/config/categories.py`.
2. Добавьте логику определения в `app/core/classifier.py`.
3. Добавьте сценарий в `app/config/scenarios.json`.
4. (Желательно) добавьте тест в `app/tests/test_classifier.py`.

После этого запустите:

```bash
pytest -q app/tests
```

---

## 8) Как понять, что отзыв нужно отправить на ручную обработку

Пайплайн вычисляет флаг `needs_manual_review` и список причин, если видит рискованный случай.

Сейчас флаг ставится, например, на такие случаи:
- очень чувствительные формулировки (например, про здоровье, претензии, суд и т.д.),
- длинные сложные негативные жалобы,
- низкая оценка без понятной причины.

Где это настраивается:

- `app/core/manual_review.py`

Флаг и причины возвращаются в артефактах пайплайна (`PipelineArtifacts.needs_manual_review`, `manual_reasons`)
и покрыты тестом `app/tests/test_pipeline_manual_review.py`. В текущем скрипте `wb_reviews_reply.py` публикация
по этому флагу не блокируется: отзывы с оценкой ниже 4 отсекаются раньше, до генерации, а флаг остаётся
заделом для шага «отложить на ручную проверку».

---

## Полезный безопасный сценарий запуска

1. `DRY_RUN=1`, проверить ответы глазами.
2. Поставить `MAX_COUNT=10` для короткого прогона.
3. Если всё хорошо — `DRY_RUN=0`.
4. Первые дни смотреть логи и вручную проверять сложные категории.
