# Автоответы на отзывы маркетплейсов: Wildberries и Ozon

Витринная копия двух рабочих сервисов бренда JE LA PECHE, которые по расписанию отвечают на отзывы покупателей:
`wb/` — Wildberries, `ozon/` — Ozon. Оба на Python (3.10+ для WB, 3.13 для Ozon), ходят в API маркетплейса и в
OpenAI Chat Completions напрямую через `requests`, без фреймворков и баз данных. Запускаются как cron-задачи: для Ozon
конфигурация деплоя есть в репозитории (`ozon/render.yaml`, Render cron каждые 5 минут), планировщик для WB в репозиторий не входит.

## Как устроен пайплайн

1. **Забрать отзывы по API.** WB: `GET /api/v1/feedbacks?isAnswered=false` постранично. Ozon: `POST /v1/review/list`
   со статусом `UNPROCESSED`; при `ONLY_UNANSWERED=1` дополнительно проверяется список комментариев к отзыву.
2. **Классифицировать.** WB: `ReviewClassifier` по правилам из `app/config/classification_rules.json`, 10 категорий
   (пустой, короткий без конкретики, размер, качество, упаковка, состояние при получении, несоответствие ожиданиям,
   нейтральный, позитив с замечанием, позитив). Ozon: `classify()` с эвристиками по ключевым словам
   (запах, ошибка при отгрузке, размер, упаковка, несоответствие фото, качество ткани, прочее).
3. **Собрать ответ по сценарию через OpenAI.** Чистые 5★ без замечаний (в WB — только короткие, до 30 символов) — локальный шаблон без модели. Иначе запрос к модели:
   системный промпт с тоном бренда плюс данные отзыва. WB подставляет сценарий категории из `app/config/scenarios.json` (цель,
   что включить, чего избегать, лимит предложений) в `app/prompts/user_template.txt`; Ozon передаёт JSON с полями отзыва и меткой классификации.
4. **Проверить текст.** Приветствие по времени суток и имени, «Вы/Вам/Ваш» с заглавной, фирменная подпись ровно один раз,
   ограничение длины, анти-повторы между ответами (`wb/app/core/postprocess.py`). В Ozon `fix_response()` дополнительно
   убирает позитивные клише при жалобе на размер или качество и дописывает помощь с размерной сеткой. WB-пайплайн также
   вычисляет флаг ручной проверки `needs_manual_review` для чувствительных случаев (`wb/app/core/manual_review.py`).
5. **Опубликовать.** WB: `POST /feedbacks/answer`; Ozon: `POST /v1/review/comment/create` с `mark_review_as_processed`.
   При `DRY_RUN=1` публикации нет.

Особенности: WB отвечает только на отзывы 4–5★; Ozon маскирует персональные данные в логах (`LOG_PII_MASK`) и отдельно обрабатывает отзывы без текста.

## Структура

- `wb/wb_reviews_reply.py` — точка входа; `wb/app/core/` — classifier, pipeline, generator (OpenAI), postprocess, manual_review, wb_api;
  `wb/app/config/` — категории, правила, сценарии; `wb/app/prompts/` — тон бренда и шаблон; `wb/app/tests/` — тесты сервиса;
  `wb/prompts/system_ru.txt` — ранняя версия промпта, кодом не используется; `wb/test_wb_api.py`, `wb/test_openai.py` —
  ручные проверки доступа к API (ходят в сеть); `wb/README.md` — исходный README сервиса.
- `ozon/ozon_reviews_reply.py` — весь сервис в одном модуле; `ozon/prompt_ozon_ru.txt`; `ozon/render.yaml` — cron-деплой на Render.
- `tests/` — unit-тесты витринной копии на чистые функции обоих сервисов; `.env.example` — все переменные, которые читает код.

## Запуск в тестовом режиме (DRY_RUN=1)

```bash
python -m venv .venv && .venv/Scripts/activate    # Linux/macOS: source .venv/bin/activate
pip install -r wb/requirements.txt -r ozon/requirements.txt
cp .env.example .env                              # заполнить WB_TOKEN, OPENAI_API_KEY, OZON_CLIENT_ID, OZON_API_KEY
cd wb && python wb_reviews_reply.py               # .env подхватывается через python-dotenv (поиск вверх от wb/)
cd ozon && python ozon_reviews_reply.py           # читает только окружение процесса: экспортируйте переменные из .env
```

По умолчанию `DRY_RUN=1`, и оба скрипта ничего не публикуют: WB печатает блок `--- DRY_RUN ---` с id, оценкой, категорией,
причинами классификации и текстом ответа; Ozon при `LOG_SHOW_LLM=1` (по умолчанию) пишет в лог строки `[LLM]` с обрезанным входом
(персональные данные замаскированы) и ответом модели; локальные шаблонные ответы в лог не попадают. Боевой режим — `DRY_RUN=0`.

## Переменные окружения

| Переменная | Сервис | Назначение |
|---|---|---|
| `WB_TOKEN` | WB | токен API отзывов WB, без префикса `Bearer` |
| `OZON_CLIENT_ID`, `OZON_API_KEY` | Ozon | ключи Ozon Seller API |
| `OPENAI_API_KEY` | оба | ключ OpenAI |
| `OPENAI_MODEL` | оба | модель; по умолчанию `gpt-4o-mini` (WB) и `gpt-5.4-mini` (Ozon) |
| `DRY_RUN` | оба | `1` — не публиковать (по умолчанию), `0` — публиковать |
| `OPENAI_PROJECT`, `OPENAI_MAXTOKENS`, `MAX_COUNT` | WB | заголовок OpenAI-Project (необязательно), лимит токенов ответа (220), лимит отзывов за прогон (50) |
| `PAGE_LIMIT` (запасной вариант — `MAX_COUNT`), `MAX_PAGES`, `ONLY_UNANSWERED`, `SKIP_EMPTY`, `MARK_EMPTY_AS_PROCESSED`, `EMPTY_REPLY_LEVEL` | Ozon | пагинация и политика для отзывов без текста |
| `LOG_LEVEL`, `LOG_SHOW_LLM`, `LOG_PII_MASK`, `LOG_MAX_LLM` | Ozon | логирование |
| `*_PATH` | оба | пути к промптам и конфигам, значения по умолчанию заданы в коде |

## Тесты

`pip install pytest && python -m pytest` запускает `tests/` (классификация темы, приветствие, «Вы» с заглавной, подпись, длина, правка
ответа при жалобе на размер; без сети) и `wb/app/tests/` (классификатор, флаг ручной проверки, клиент WB API с подменой `requests`); ручные `wb/test_*.py` не собираются.

## Что удалено в витринной копии и почему

- `.env` и `.venv/` рабочего окружения: секреты и окружение не публикуются, имена переменных перенесены
  в `.env.example` с пустыми значениями.
- Git-история: копия начинается с одного коммита, история разработки остаётся в приватном репозитории.
- Логов прогонов и персональных данных покупателей в исходниках не было, переносить было нечего.

## Статус

Оба сервиса работали в проде на обоих маркетплейсах. Код ведётся в приватном репозитории с сентября 2025 (WB)
и октября 2025 (Ozon); здесь очищенная копия без истории. В `ozon/render.yaml` задан `DRY_RUN=1`: для боевого режима
переменную переопределяют в настройках сервиса. Для запуска нужны собственные токены WB и Ozon и ключ OpenAI.
